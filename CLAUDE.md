# CLAUDE.md

QSBuddy is a browser-based editor and librarian for Alesis QS synths (QS6/7/8/R), over Web MIDI. The owner uses a QS7. Read `docs/architecture.md` before changing the codec or MIDI path, and `docs/roadmap.md` for what's next.

## Commands

```bash
npm test                 # node --test tests/*.test.js (Node 22+, no dependencies)
npm run build:library    # regenerate app/library/ from archive/ (Python 3, stdlib only)
npm run serve            # serve app/ at http://localhost:8765
```

To check UI changes without hardware, open `app/index.html?demo` (simulated QS7). Add `&progsel=off` or `&sysex=off` to simulate a QS ignoring program changes or a MIDI chain that drops SysEx.

## Layout

- `app/`: the static web app. Classic `<script>` files on `window.QS`; no build step, and it must keep working from `file://`. Don't convert to ES modules without a deliberate decision.
- `app/js/qs-sysex.js`, `app/js/qs-params.js`: pure codec and parameter tables; also loaded by the Node tests.
- `app/library/`: generated by `tools/build_library.py`. Don't hand-edit; change `COLLECTIONS` or `CARDS` in the script and rebuild.
- `docs/spec/QS678R-sysex-spec.txt`: the Alesis SysEx spec. Every address, limit and opcode must come from here, written in its own `hi:bit-lo:bit` notation.
- `archive/`: the original fork's files. Treat as read-only source material; reference it from tools, don't edit it.

## Rules

- Patch changes from synth banks send plain Bank Select (CC 0) + Program Change only. Don't add SysEx in front of them without testing on real hardware.
- Anything that writes synth memory (User dumps, bank writes) needs a confirm dialog that shows what gets overwritten.
- Codec changes need tests against real files in `archive/`; decode/encode round-trips must stay byte-identical.
- On Windows only one app can open a MIDI port, and many MIDI chains and cheap cables drop SysEx. Keep failures visible to the user (toasts, the connection test), never silent.
